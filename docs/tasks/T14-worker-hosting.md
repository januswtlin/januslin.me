# T14: Worker, wrangler config, headers

- Role: Platform Engineer
- Depends on: T09 · Human steps: T14-H1, T14-H2, T14-H3. Integration with T13's `.md` outputs uses fixtures until T13 merges.
- Identity: app (`januslin-agent[bot]`)

## Goal
The site runs as the Worker `januslin-me` with static assets, serves Markdown to agents that ask for it, and sends strict security headers. Production custom domains are **not** attached yet (T17).

## Read first
`docs/overview.md`, `docs/deployment.md`, `docs/security.md`, `ADR-0002`, current Cloudflare docs: Workers static assets (configuration, `run_worker_first`, `_headers`, `_redirects`), preview URLs, custom domains.

## Scope
- `wrangler.jsonc` per `docs/deployment.md`, **without `routes`** (added in T17; attaching `januslin.me` now would collide with the live Pages project). `workers_dev: false`, `preview_urls: true` (with `workers_dev` off, preview URLs are disabled unless set explicitly; Cloudflare docs, verified 2026-10-27), `account_id` in the file. Preview URLs are public until T15 runs, so T14 uploads fixture content only.
- `worker/index.ts`: for requests matched by `run_worker_first`:
  - `Accept` includes `text/markdown` (and prefers it over `text/html`): fetch `<path>index.md` from `ASSETS`, return it with `Content-Type: text/markdown; charset=utf-8`, `Vary: Accept`, and caching headers equal to the HTML's.
  - Otherwise: pass through to `ASSETS`, add `Link: <…/index.md>; rel="alternate"; type="text/markdown"` and `Vary: Accept`.
  - Missing `.md`: fall through to HTML.
- Evaluate the Transform Rule alternative described in ADR-0002 (Free plan feasibility of the needed rewrite expression). Write the decision as an ADR-0002 addendum. Implement only the chosen mechanism.
- `run_worker_first` covers topic paths, page paths, and their `/en/` mirrors, generated by `scripts/sync-worker-routes.ts` (T10) from `content/topics/` and `content/pages/`; CI runs it in `--check` mode.
- CI-checkable guard: a test that loads `wrangler.jsonc` and fails if any `run_worker_first` pattern could match `/_astro/`, `/fonts/`, or common image/font/feed extensions.
- `public/_headers`: security headers from `docs/security.md`; long-term immutable caching for `/_astro/*` and `/fonts/*`. Preview builds additionally send `X-Robots-Tag: noindex` site-wide (build-time variant of `_headers`).
- `public/_redirects`: empty with a header comment explaining its use for slug changes.
- Local: `pnpm wrangler dev` serves `dist/` with the Worker; document in `AGENTS.md` commands if changed.
- Verify the deploy token's minimum scopes with a real `wrangler versions upload` to a preview alias, run in the sandbox with a short-lived token that the proxy injects for `api.cloudflare.com` (V25) the author hands over for this task (T14-H1) and revokes afterwards (T14-H3); update `docs/security.md` with the verified minimum. The author then creates the real deploy token with those scopes and stores it in both environments (T14-H2); no agent ever sees it.

## Out of scope
Workflows (T16). Access (T15). Custom domains and DNS (T17).

## Human steps

Only the author can do these. The agent prepares each one with the exact values before it is needed and waits for the reply. Never paste a secret into a chat; where a secret is involved, the step stores it directly.

- **T14-H1, short-lived Cloudflare token (10 min).** This is the "ops token" procedure; T15 and T17 refer to it. Cloudflare dashboard → My Profile → API Tokens → Create token → Custom: the scopes the agent sends (for T14: the deploy scopes in `docs/security.md`), TTL one day, client IP filter off. Copy it. In your Terminal: `sudo -u Agent sh -c 'umask 077; read -rs T; printf %s "$T" > /Users/Agent/.local/state/januslin-agent/cloudflare-ops.token'`, paste, Enter. Then in `agent-session`: `sbx secret set-custom --sandbox januslin --host api.cloudflare.com --env CLOUDFLARE_API_TOKEN --command 'cat /Users/Agent/.local/state/januslin-agent/cloudflare-ops.token'` and `sbx policy allow network --sandbox januslin api.cloudflare.com`. Send the agent: "token handed over".
- **T14-H2, the deploy token (10 min).** Create the deploy token with the scopes T14 verified (in the PR), expiry one year from today (send the agent the date for the calendar in `docs/operations.md`), then in your Terminal: `gh secret set CLOUDFLARE_API_TOKEN --env production --repo januswtlin/januslin.me` and the same with `--env preview` (each prompts for the value). Send the agent: "T14-H2 done".
- **T14-H3, revoke (2 min).** When the agent says it is finished: delete the T14-H1 token in the Cloudflare dashboard and run `sudo -u Agent rm -f /Users/Agent/.local/state/januslin-agent/cloudflare-ops.token`; in `agent-session` remove the custom secret (`sbx secret ls --sandbox januslin` shows its name; `sbx secret rm` it) and the policy rule (`sbx policy rm network --sandbox januslin --resource api.cloudflare.com`). Send: "revoked".

## Acceptance criteria
- [ ] `pnpm build && pnpm wrangler dev`: `curl -H 'Accept: text/markdown' localhost:8787/<topic>/<fixture>/` returns Markdown with correct headers; same URL without the header returns HTML with the `Link` header.
- [ ] Requests for `/_astro/*.css` and images do not invoke the script (verify via `wrangler dev` logs or Worker observability on a preview).
- [ ] A preview version uploaded with `--preview-alias t13` is reachable at its preview URL and behaves as above.
- [ ] securityheaders.com-equivalent check (or a test) shows all headers from `docs/security.md` on HTML.
- [ ] A test asserts, for a content page **and** the 404 page (`_headers` patterns can miss `404.html`): `script-src` has no `'unsafe-inline'`, `'unsafe-eval'`, `data:`, or `blob:`; `object-src 'none'`; `base-uri 'self'` or `'none'`. This is defense in depth against XSS from `content/`. If the theme needs an inline script, use a hash, not `'unsafe-inline'`.
- [ ] ADR-0002 addendum written; `docs/deployment.md` and `docs/security.md` updated to the verified reality.

## Automated verification
What this task adds to `pnpm verify` (ADR-0010), and what stays manual.
- Worker unit tests (Vitest with `@cloudflare/vitest-pool-workers`) for Markdown negotiation, the `Link` header, `Vary`, and the fall-through when `.md` is missing.
- An integration test starts `wrangler dev` on a free port with `WRANGLER_SEND_METRICS=false` (no external request) against `dist/` and asserts the `curl` ACs (Markdown with `Accept: text/markdown`, HTML with `Link` otherwise).
- Config tests: the `run_worker_first` guard; `_headers` parsed for a content page and `404.html`, asserting every header from `docs/security.md` and the CSP rules in the ACs.
- Manual: the preview upload (needs the T14-H1 token), and whether static assets invoke the script on a real preview.
